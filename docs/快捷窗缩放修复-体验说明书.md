# 桌面待办 · 快捷添加窗缩放抖动修复 体验说明书

> 依据：《技术手册-快捷窗缩放修复-移植Electron版.md》（唯一实施方案，2026-10-14）｜基线：8e51929（v1.1.2-L2）
> 范围：只动快捷添加窗的缩放路径；待办主窗、已完成窗缩放机制**不动**。

---

## 一、这批做什么（一句话）

把快捷添加窗从"**缩放时窗口矩形逐帧变 + 内容跟着重排**"改成"**窗口矩形恒定不动、内容整体缩放**"——窗口框不再逐帧变，"框先到、内容晚一拍"的抖动从根上消失；缩放全程内容可见。

## 二、你现在看到的（对照着验收）

拖住主窗右下角缩放柄放大/缩小时，快捷添加窗：

1. **框先到、内容晚一拍**：窗壳先缩到位，里面文字/列表慢 1~2 帧才跟上（拖影/错位）；
2. **缩放中内容变底色**：为压住拖影，现在缩放期间快捷窗内容被替换成纯底色，松手才恢复——等于缩放时"看不到内容"；
3. **缝隙摆动**：快捷窗与主窗之间的 4px 缝隙在缩放中轻微变宽变窄（±1px 取整摆动）；
4. 按下手柄、松开手柄各闪一次。

## 三、修完后你会看到（分四步交付，每步一次真机确认）

| 步 | 你会感觉到的变化 | 说明 |
|----|------------------|------|
| 1 | 快捷窗**窗壳在缩放中完全不动**（位置和大小都恒定），里面内容**整体、同帧**跟着手势变大变小；缝隙不再摆动；按下/松手不再闪 | 窗口改成恒定"画布"（按当前屏幕能达到的最大档预留），卡片内容在画布内右上角对齐、整体缩放 |
| 2 | 缩放**全程内容可见**——"变底色"从快捷窗消失 | 主窗/已完成窗的缩放呈现不变（那两窗的轻微"框先到"你已确认可接受） |
| 3 | 卡片外的透明画布余量**不再吞桌面点击**：可以正常点选/框选画布余量区域的桌面图标 | 画布比卡片大一圈（预留最大档），第 1 步落地后这块区域暂时吞点击（见下方过渡态），第 3 步消除 |
| 4 | （可选）松手后文字做一次"锐化落地"，静止态像素级锐利 | 仅当真机看缩放后静止文字明显发糊才做；默认不做 |

**⚠ 已知过渡态（必须知晓）**：第 1 步交付后、第 3 步之前，快捷窗卡片左侧/下方的透明画布余量**会吞掉落在那块的鼠标点击**（桌面上那块区域点不动图标）。这是方案的已知中间状态，第 3 步消除。如果你在此期间常用那块桌面，可先停在"已回退的干净状态"等第 3 步一起验收。

## 四、怎么操作验证（真机）

1. **窗壳恒定**：拖缩放柄来回缩放，眼睛盯快捷窗**外框**——四条边应该全程纹丝不动（现状：框跟着缩放走）。
   我的交付证据：缩放拖动中逐帧打印快捷窗 getBounds()（宽/高/x/y 恒定不变日志），你可以复跑。
2. **内容跟手**：缩放中文字列表与手势**同帧**缩放，无"先弹再回"、无底色期、无拖影。
3. **缝隙**：手机慢动作录屏缩放过程，逐帧量"主窗左缘 ↔ 快捷窗右缘"缝隙——像素差恒定（不再 13→17→13 式摆动）。
4. **命中**（第 3 步后）：把桌面图标放到快捷窗透明余量下方，点击/框选应正常选中。
5. **回归**：快捷窗的显隐开关（⚡ 按钮）、批量、模板添加、拖动整簇移动、贴边缩进弹出、置顶、跨屏拖动——手感与现在完全一致；主窗/已完成窗缩放手感不变。
6. **清晰度**：松手后静止态文字应锐利；若缩放后明显发糊 → 启用第 4 步（单独一笔，可回退）。

**什么算通过**：1~5 全部满足 + 全部自动化测试绿；观感结论以你真机判断为准。
