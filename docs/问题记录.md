## A. 系统快捷键与显隐

### A1. Win+D 隐藏组件（2026-09-25 提出，2026-10-05 语义定稿关闭）
- 诉求：组件不应受 Win+D（显示桌面）影响（最初口径）。
- 根因：Win11 26200 的 Show Desktop = DWM 合成层隐藏，零事件零状态，仅豁免 toggle 时刻已在置顶层/shell 拥有的窗口；事后补救（重设置顶/hide+show/改 owner/竞态抢跑/钩子内抢设）全部无效或不确定。
- 处置：历经 TOOLWINDOW→cloak 轮询→钩子抢跑（多轮真机失败）→ **语义定稿（用户裁定）**：置顶态天然免疫；未置顶=普通窗口行为（可被隐藏，再按 Win+D 恢复）。
- 状态：✅ 已关闭（2026-10-05 语义最终版，260259a）。

### A2. Win+M 不作用于组件（2026-10-06 提出，已裁定+已撤回实现）
- 诉求演进：Win+M 两态生效 → 诊断 → **最终裁定（2026-10-06）：回归系统默认，不做技术干预、不做要求**；相关语义已写入需求文档 v1.3 章节。
- 根因（Shell COM MinimizeAll 诊断实锤，与 Win+M 同一代码路径）：`TOOLWINDOW + skipTaskbar`（不进任务栏/Alt+Tab 的既定设计）把组件排除在 shell 应用窗口清单之外，Win+M 只作用于该清单。**补充（用户实测纠正）：二级窗同样 skipTaskbar 隐身，Win+M 对其同样无效——全应用统一隐身，无一窗口在 shell 清单内。**
- 测试保真度教训：E2E 用 `ShowWindowAsync(SW_MINIMIZE)` 直接 API 当"Win+M 等价物"是错误前提——直接调用绕过 shell 枚举，测试绿而真机无效；**涉及 shell 行为的功能只能真机验收**。
- 处置：实现已撤回（git revert a87315b→9b25b87，恢复 minimizable:false+置顶兜底=用户验收过的语义最终版状态）；E2E 注释更正（移除"Win+M 等价物"错误标注）。
- 状态：✅ 已关闭（回归默认）；**与三窗架构的关联归入 §D6 架构讨论**。

### A3. Alt+F4 语义（2026-10-04 提出，三次口径演进，2026-10-05 定稿）

- 处置：cluster 窗口/二级窗 close 事件（无意图标记）→ app.quit()；二级窗 ×/←（closeSelf）带意图标记仅关自己；before-quit 数据落盘照走。

## C. 渲染交互缺陷

### C1. 气泡弹窗卡死（2026-10-05 报告）
- 现象：双击待办/模板文本 → 二级窗与气泡同时出现，气泡不因鼠标移开消失。
- 根因（已定位）：二级窗打开 → 三窗 setEnabled(false)（模态锁）→ 禁用窗口不收鼠标事件 → 文本 mouseleave 丢失 → hideBubble 永不触发。
- 处置 v1：veil/失焦 → hideBubble()（3f11537）——真机复测仍未解决。
- 根因 v2（2026-10-07 fake-timers 实锤）：气泡显示有 1s 延迟定时器，禁用窗口收不到 mouseleave 后**排队中的定时器到点照弹**——v1 只隐藏了已显示的气泡，未取消排队中的定时器。
- 处置 v2：content-bubble 导出 cancelBubble()（清定时器+清悬停状态+抑制标志+隐藏），veil/失焦改调（2952b59）；**气泡延迟 1s→0.5s**（用户 2026-10-07 裁定）。
- 状态：⏳ v2 已实施，待真机复测；若仍复现需在复现时记录操作序列（悬停时长/双击间隔）。

### C2. 文本编辑光标位置失效（2026-10-06 报告）
- 现象：编辑模板/待办 textarea 内，鼠标点击任意位置或方向键都无法移动插入点，编辑只发生在文本末尾。
- 根因：待诊断（静态排查排除：值重写有 touched 守卫、子窗无 zoom、无 drag 区覆盖；候选=user-select 继承/焦点竞争）。
- 诊断（e4d60ff）：CI/自动化环境下点击定位与方向键移动插入点**均正常**（selectionEnd 点击 x=20→1、ArrowRight→2）——真机无法复现，需用户下次操作时配合复现（记下当时窗口/缩放状态）。
- 措辞更正（2026-10-08 用户指出）：用户从未报告光标闪烁有问题——提出的是**编辑时光标常显的优化请求**；诊断日志证实插入点模型层一直正常（点击 sel=150/269、退格逐字删除于插入点）。
- 关联优化（用户提出"编辑时光标常显"）：v1 尝试 solid-caret（40ms 透明/主题色交替重绘）——接线修复后真机实测为**高频快闪**（12.5Hz 明灭可辨），比原生更差；用户裁定恢复 ea445c1 行为（2026-10-08）。
- **定论**：Chromium 原生光标即"输入/删字/移动期间常亮、停手恢复闪烁"——用户要的效果是原生自带，任何自绘干预都属画蛇添足。solid-caret util/测试/两窗接线已全部移除。
- 状态：✅ 已关闭（回归原生光标）。
